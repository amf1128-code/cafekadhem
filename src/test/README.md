# Tests

Vitest + React Testing Library. Configured in `vitest.config.ts` (separate
from `vite.config.ts` so dev/build are unaffected).

## Run

```sh
npm test           # one-shot
npm run test:watch # re-run on file changes
npm run test:ui    # vitest browser UI
```

## Patterns

### Mocking Supabase

The cinema components import `supabase` from `../../lib/supabase`. Each
test that hits Supabase uses `vi.mock` to swap that import for a stub
generated by `src/test/mocks.ts`:

```ts
vi.mock('../../lib/supabase', () => ({
  supabase: makeSupabaseStub({
    tables: { events: { data: rows } },
    rpcs: { get_my_guest: null },
  }),
}))
```

`vi.mock` is hoisted to the top of the file at parse time, so any
fixture data referenced inside the factory must be wrapped in
`vi.hoisted({...})` so it's lifted with the mock — see
`CinemaCalendar.test.tsx` and `CinemaEventDetail.test.tsx` for the
pattern.

### Pinning the clock without breaking promises

Several flows depend on `Date.now()` (isUpcoming, calendar partitioning).
Use `vi.useFakeTimers({ toFake: ['Date'] })` instead of the default
`vi.useFakeTimers()` — the latter swaps timer scheduling out for a fake
queue, which prevents Supabase mock promises from resolving inside
`useEffect`. Limiting to `Date` only freezes time without breaking the
microtask scheduler.

```ts
beforeEach(() => {
  vi.useFakeTimers({ toFake: ['Date'] })
  vi.setSystemTime(new Date('2026-05-01T12:00:00Z'))
})
```

### CSS uppercase ≠ DOM text

Cinema cells use `text-transform: uppercase` for visual polish, but the
underlying text node is the original case from the database. Match what
the data has, not what the eye sees:

```ts
// ✗ DOM text is "Pistachio Bun"
expect(screen.getByText('PISTACHIO BUN'))

// ✓
expect(screen.getByText('Pistachio Bun'))
```

## What's not covered (yet)

These would be good targets for follow-up work:

- **RSVPForm** — heavy form, mostly side effects. Consider Playwright /
  Cypress against a real Supabase test project rather than mocking the
  intricate plus-one + merge-verification logic.
- **Order / Pickup / PickupTicket** — same shape as the cart modal,
  test coverage there is the highest-leverage addition.
- **Identity recognition refresh** — `useMyGuest` listens for
  `GUEST_TOKEN_EVENT` and `storage` events; tests should fire those and
  verify the strip updates without a remount.
- **Magic link redemption** — `MyTickets` redeems `?t=` tokens via
  `redeem_magic_link`; cover the success / expired / unknown branches.
- **Ticket QR rendering** — `CinemaTicket` calls `QRCode.toDataURL`;
  mock the qr lib and assert the encoded URL matches `/ticket/:token`.
- **End-to-end smoke** — a single Playwright happy-path against a real
  Supabase test project would protect the full RSVP → pre-order →
  Venmo → confirmation flow.

## Adding a test

Tests live next to the code they test (`foo.test.ts` next to `foo.ts`).
Vitest picks up anything matching `src/**/*.{test,spec}.{ts,tsx}`.

For component tests:
- Mock Supabase first with `vi.mock('../../lib/supabase', ...)` (note
  the path is relative to the test file).
- Wrap the component in `<MemoryRouter>` if it uses any router hooks.
- Prefer `screen.findBy*` over `await waitFor(() => screen.getBy*)` —
  it's the same thing but reads more directly.
- Reach for `userEvent.setup({ advanceTimers: vi.advanceTimersByTime })`
  whenever the test is using fake timers, otherwise click handlers can
  hang waiting for fake setTimeout to advance.
